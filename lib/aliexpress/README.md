# AliExpress integration\n\n## Developer-guide mapping\n\nThis app primarily uses the **DropShippers API Developer** family. The guide's three areas have different roles:\n\n- **DropShippers API Developer** — product discovery, DS-context SKU pricing, destination freight, address validation and DS ordering. This is the core sourcing/commerce integration.\n- **Overseas Developers** — merchant/store-management APIs for AliExpress-managed or cross-border businesses. These are not used as a substitute for DS product sourcing.\n- **Affiliate Developers** — affiliate attribution/deep-link capabilities. Add these only when the storefront needs affiliate commission tracking; they are not the source of our canonical product cost.\n\n## Product acquisition flow\n\n```text\nlocal product\n   ├── text search ─────┐\n   ├── image search ────┤\n   │                    ↓\n   │              candidate products\n   │                    ↓\n   │             ds.product.get\n   │                    ↓\n   │          exact SKU/product data\n   │                    ↓\n   │             ds.freight.query\n   │                    ↓\n   └──────────── landed-cost engine\n                        ↓\n                  storefront/matching\n```\n\nSearch APIs are candidate discovery. `aliexpress.ds.product.get` is the canonical product/SKU hydration step, and `aliexpress.ds.freight.query` verifies destination-specific shipping for the exact SKU.\n\n## Available services\n\n- `getAliExpressProduct()` — product details, variants, stock, images and DS-context SKU pricing; cached and persisted to Neon.\n- `searchAliExpressText()` — keyword discovery with the documented search filters.\n- `searchAliExpressByImage()` — same/similar product discovery from an image.\n- `discoverAliExpressProducts()` — merges text and image candidates by product ID.\n- `getAliExpressFeedItemIds()` — retrieves item IDs from an approved DS feed name for scalable catalog acquisition.\n- `getAliExpressFreight()` — exact SKU + destination freight options.\n- `getAliExpressAddressTree()` — AliExpress-supported province/city hierarchy for checkout validation.\n- `createAliExpressDsOrder()` — isolated order-placement service; browsing never places an order.\n\n## Pricing layers\n\nFor each SKU we retain the distinction between:\n\n1. `skuPrice` — the API's Origin SKU price.\n2. `offerSalePrice` — the API promotional/offer price.\n3. `itemPrice` — the effective price currently used by the existing comparison pipeline.\n4. Freight — destination and exact-SKU dependent.\n5. Tax flags — including `priceIncludeTax`; the freight response may also indicate tax-inclusive/DDP behavior.\n6. FX and the project's landed-cost rules.\n7. Customer sell price — applied only after landed cost and markup rules.\n\nThe API documentation notes that API pricing can depend on account/context and can differ from the public web page. We therefore do not call the API price the public retail price.\n\n## Scalable catalog acquisition\n\nThe documented DS feed pattern is:\n\n```text\nfeed/recommendation\n       ↓\nfeed name\n       ↓\nfeed.itemids.get\n       ↓\nitem IDs\n       ↓\nproduct.get\n       ↓\nNeon canonical catalog\n```\n\nWe deliberately do not hard-code a feed name because the official documentation says feed names are obtained from the recommendation/feed API and can be customized by the business team.\n\n## Checkout/address rule\n\n`aliexpress.ds.address.get` should be used to validate/resolve the customer's province and city before `aliexpress.ds.order.create`. A typed Kenyan county/city is not automatically assumed to be an AliExpress-valid value.\n\n## What remains intentionally separate\n\n- Matching is still a human-reviewable enrichment process; fetching a product does not create a match.\n- Fetching does not automatically publish an AliExpress SKU.\n- Search prices are not final landed costs.\n- We do not invent Kenyan duty/tax formulas from incomplete AliExpress freight data.\n- Automatic token refresh still needs to be implemented from the exact OAuth documentation before unattended long-term synchronization.
